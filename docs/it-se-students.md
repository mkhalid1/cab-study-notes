# IT・SE志望の就活生へ

CABを受けるのは、多くの場合、SE・プログラマー・インフラエンジニアなどの技術職に応募した人です。このページでは、IT業界を目指す就活生に向けて、CABを選考の中でどう位置づけ、どう準備すればよいかをまとめます。

## 選考の中でのCAB

日本SHLは、CABの結果を初期スクリーニングだけでなく、面接での確認、内定者へのフィードバック、配属の検討などにも使えると説明しています。つまり、CABは「通過すれば終わり」のテストとは限りません。

| 場面 | CABとの関係 |
|---|---|
| エントリー直後 | Web-CABの受検案内が届くことがある。締切が短いこともあるので早めに確認する |
| 書類・適性検査の選考 | 能力科目の結果が、通過の判断材料の1つになる |
| 面接 | 性格検査の結果が、質問のきっかけとして使われることがある |
| 内定後・配属 | 結果をもとにフィードバックや配属の検討が行われることがある |

どの段階で何に使うかは企業によって違い、外からはわかりません。

## 文系・未経験でも不利になりにくい理由

日本SHLは、CABが測る知的能力は「ITやプログラミングに関する知識を問わない」もので、エンジニア未経験者にも使えると説明しています。実際、問題は計算と図形だけで、コードは1行も出てきません。

だからこそ、情報系の学生でも油断は禁物です。プログラミング経験は命令表や暗号の考え方を理解する助けにはなりますが、形式に慣れていなければ時間内に解けません。逆に、文系の学生でも形式に慣れれば十分に戦えます。

## プログラミングとのつながり

各科目は、エンジニアの仕事のどこにつながっているのでしょうか。日本SHLの説明をもとに、このガイドの言葉で整理すると次のようになります。

| 科目 | 日本SHLの説明 | 仕事で近い場面 |
|---|---|---|
| 暗算（四則逆算） | デジタル関連職に必要な基礎能力 | 見積もり、性能の概算、ログの数字の確認 |
| 法則性 | プログラマーとしての優秀性 | ループの中の変数の変化を追う、データの傾向を読む |
| 命令表 | コンピュータ言語への適応の度合い | 仕様どおりに処理を順番に実行する、コードを読んで動きを追う |
| 暗号 | 複雑なシステム設計への適性、デバッグ能力 | 入力と出力から不具合の原因を推理する |

面接で「CABの暗号が楽しかった」と話す必要はありませんが、この対応を知っておくと、各科目の考え方が腹落ちしやすくなります。

## 面接に向けて準備しておくこと

性格検査の結果は面接の質問のきっかけになることがあります。技術職の面接でよく聞かれるテーマについて、具体的なエピソードを1つずつ用意しておくと安心です。

- **新しい技術をどう学んだか。** 授業、独学、インターンなど。CABが測る「技術習得のポテンシャル」と直結する話題です。
- **チームで何かを作った経験。** 役割、意見が割れたときの対応、最後にどうなったか。
- **うまくいかなかったことへの対処。** バグ、締切、想定外のトラブル。原因をどう突き止めたか。

## 並行して受けることが多い検査

IT企業の選考では、CABのほかにSPIや玉手箱、GABなどを課す企業もあります。日本SHLの検査の中では、玉手箱Ⅲにも「計数（四則逆算）」があるので、CABの計算の練習は玉手箱の対策にもなります（[CABとは](test-overview.md#よく似た検査との違い)を参照）。

## まずやること

1. [15分診断テスト](diagnostic.md)で苦手な科目を見つける。
2. 受検の締切から逆算して、[7日間プランか2日間プラン](study-plans.md)を選ぶ。
3. 時間を計った通しの練習を1回はしておく。[CAB形式の無料模擬テスト（PrepClubs）](https://prepclubs.com/ja/cab-taisaku?utm_source=github&utm_medium=referral&utm_campaign=srubdn&utm_content=cab)で4科目を通して解けます。
